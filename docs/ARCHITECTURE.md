# 설계·확장 지점·알려진 한계

## 경계

- `FishingMachine`: 시간 기반 V1 입력 상태. 순수 Luau이므로 CLI에서 실제 모듈을 실행해 검증합니다.
- `FishingService`: 서버 위치·장비 검사, 서버 시계, 입력 빈도 제한, 찌 표시, 완료 세션 소비. 성공할 때만 `Domain.grant`를 호출합니다. 보상 종·GUID·알 시드는 서버에서 생성합니다.
- `Domain`: 소유자 프로필 내 개체 상태 변경. 클라이언트가 가격·종·확률·수량·버프를 지정할 수 없습니다.
- `ProfileStore`: 프로필 하나에 대한 직렬화·복제·검증·영속 커밋·복제본 게시. 저장 확인 전 UI/3D에 새 보상을 노출하지 않습니다.
- `WorldService`와 `Effects`: 저장 데이터로부터 만들어지는 시각적 표현입니다. 모델의 위치나 Attribute를 바꾸어도 아이템 소유권은 바뀌지 않습니다.
- `Main.client`: 캐스팅·포획 입력과 스냅샷 표시. 클라이언트 미니게임 값은 서버 결과를 보여주는 용도입니다.

낚시 V2에서는 `FishingMachine`, `FishingService`의 입력 처리, 클라이언트 입력 위젯을 교체할 수 있습니다. 물고기·알 추첨, 개체 저장, 부화·소비 규칙은 유지할 수 있습니다. 현재 캐스팅은 부두에서 연못 방향으로 자동 조준되며 수중 찌 직접 조종은 없습니다.

## 개체와 트랜잭션

프로필: `schema`, `revision`, `coins`, `items[id]`, `feed`, `aquariumLevel`, `equippedPet`.

개체: `id`, `species`, `kind`, `location`, `obtainedAt`와 종류별 데이터. 소유권은 **서버가 선택한 플레이어의 프로필에 ID가 있는지**로 판단합니다. Remote에 소유자·가격·종·보상량을 입력하는 경로는 없습니다.

- 물고기: `growth={stage=0,experience=0,evolutionVersion=1}`. 실제 성장·진화 기능은 없습니다.
- 알: 획득 시 서버 시드, 배치 시 `startedAt`, `readyAt`, `feedQuality`, `incubationLevel`을 저장합니다.
- 펫: 알 ID를 유지하며 `originEgg`, `hatchedAt`, `incubation` 출처를 저장합니다.

알에서 펫으로의 전환은 하나의 후보 프로필 안에서 수행한 뒤 전체를 한 번 저장합니다. 같은 ID를 알과 펫에 중복 배정하지 않습니다. 저장된 시드와 배치 조건으로 결과를 계산하므로, 이전 상태를 재실행하더라도 결과가 바뀌지 않습니다. `seed`는 클라이언트 스냅샷에서 제거됩니다.

프로필 변경은 yield 이전에 `busy`를 확보합니다. 후보 복제본에서 권한·상태·수량·비용을 검사하며, 실패한 후보는 폐기합니다. 지속 저장을 성공한 뒤에만 현재 프로필을 교체합니다. 잡은 물고기 수용량 초과 시 보상을 버리고 성공 표시하지 않도록 실패를 반환합니다. 낚시 시작 때도 한도를 검사합니다.

## 저장 방식

`UpdateAsync`로 데이터와 세션 잠금을 함께 갱신합니다. `Lease`는 다른 활성 세션, 만료된 작성자, 더 오래된 revision을 거부합니다. 업데이트 콜백에는 랜덤 생성·ID 발급·외부 부작용·yield가 없습니다.

보상·판매·제작·배치·부화·업그레이드·장착은 매번 커밋합니다. 별도의 변경사항 배치 저장을 기다리지 않아 정상 종료 시 복구 범위가 명확합니다. 단, 큰 동시접속 규모에서는 저장 요청 수 최적화가 필요합니다. 종료 시 잠금을 해제하며, 비정상 종료 시 180초 후 만료됩니다.

연결·저장 실패는 최대 3번 시도하며 재시도 간격은 1초·2초입니다. 저장 실패나 잠금 상실 시 세션을 동결하고 오류 표시 후 접속을 종료합니다. 응답 유실로 저장 여부가 불확실해도 새 보상을 먼저 표시하지 않습니다. 다음 접속은 마지막 영속 상태를 불러옵니다. 클라우드 오류를 임시 데이터로 대체하지 않습니다.

## 입력·보안

낚시 입력은 평균 초당 22개 / 버스트 30개, 일반 작업은 평균 초당 2개 / 버스트 5개로 서버에서 제한합니다. 저항 연타는 별도 최소 간격 0.075초를 검사합니다. 유지 입력은 0.5초 내 새 메시지가 없으면 만료됩니다. 긴 서버 프레임으로 게이지를 건너뛰지 않도록 단일 계산 `dt`를 최대 0.15초로 제한합니다.

클라이언트에서 `start`, `release`, `hold`, `stopHold`, `tap`, `cancel`만 전송합니다. 파워·포획 성공 여부·게이지·연타 완료 여부·추첨 결과는 클라이언트가 전달하지 않습니다. 클라이언트 조작 자동화까지 판별하는 안티봇 시스템은 이번 범위가 아닙니다.

수족관 배치·회수·업그레이드, 상점 판매, 공방 제작에는 살아 있는 캐릭터와 해당 장소와의 거리 검사가 적용됩니다. 개인 수조는 서버 할당표로 선택합니다. 디버그 지급은 Studio에서만 허용합니다. 알 회수와 부화 조건 변경을 막아 시간·확률 재선택을 방지합니다.

## 향후 우선순위

1. 제공된 Studio 승인 테스트 실행 및 실제 엔진 오류·터치 사용성 수정.
2. 실제 Roblox DataStore 장애·예산·장시간 접속·2인 이상의 재접속 스트레스 검증.
3. 모바일 실제 기기의 조작·글자 크기·프레임 성능 조정. 현재 16수조 × 최대 10개 모델은 서버 데이터와 별개로 클라이언트에서 30Hz 표시합니다. 거리별 표시 빈도 조절을 추가할 수 있습니다.
4. 무작위 분포·낚시 시간·판매 및 사료 효율을 실제 플레이 기록으로 조정. 현재 수치는 테스트용입니다.
5. 요청 ID 기반 영수증·고급 데이터 마이그레이션·운영용 복구 도구. 현재 개체 ID·상태·revision·프로필 잠금으로 중복 효과를 차단합니다. 일반적인 요청 영수증 이력은 구현하지 않았습니다.
6. 새 물고기 콘텐츠를 Catalog에 추가하고 성장·진화 서비스를 별도 모듈로 개발.
7. V2 입력/찌 조종 구현. 현재 보상·인벤토리 경계를 유지.

## 제공 상태

이번 환경은 Linux CLI이며 Roblox Studio는 설치되어 있지 않습니다. UI 렌더링, 실제 캐릭터·지형 상호작용, 로컬 멀티플레이 및 실제 클라우드 저장에 대해서는 실행 성공을 주장하지 않습니다. 스크립트 언어 검사·도메인 실행·저장 모킹·Rojo 직렬화·빌드 내 소스 일치는 검증했습니다.

일반 공개, Robux 결제, 외부 분석 수집, HTTP 네트워크 호출, 플레이어 간 거래 기능은 없습니다. 이름·색·간단한 Part 모델은 이 프로젝트에서 작성했습니다. 제3자 게임의 스프라이트·음원·모델은 포함하지 않습니다.
