# FILAMENT 0.1.1 — 실제 Roblox Studio QA

**아래 모든 항목은 현재 미실행입니다.** 체크박스는 검수자가 실제로 수행한 뒤 기록하세요. 자동 테스트 통과와 실제 Studio 승인은 다릅니다. Studio에서 출력되는 오류, 화면 크기, 입력 장치, 저장 모드를 함께 기록합니다.

## 준비

1. 새 파일 `build/FILAMENT-Fishing-0.1.1.rbxl` 또는 `.rbxlx`를 Studio에서 엽니다. 별도 플러그인이나 오브젝트 배치가 필요하지 않습니다.
2. Output 창을 열고 **Play / F5**를 누릅니다. `Run`이 아니라 플레이어를 생성하는 Play를 사용합니다.
3. 기본 `StudioPersistence=false`를 유지합니다. 처음 안내와 가방 → ? 도움말에서 임시 저장을 확인합니다. Stop하면 초기화되는 것이 정상입니다.
4. 빠른 준비는 가방 → ? → Studio 전용 테스트를 펼쳐 지급 팩을 사용합니다. 일반 이동 검수에서는 이 메뉴의 순간이동을 쓰지 않습니다.

## 화면과 입력 — 네 환경에서 반복

## 낚시 전체 상태

- [ ] 스폰에서 앞의 목재 부두로 걸어갑니다. F 또는 작은 조작 힌트/모바일 원형 버튼을 **누르기 시작**하면 캐스팅 게이지만 나타납니다.
- [ ] 약 1초 후 놓습니다. 주황 찌가 곡선으로 날아 수면에 도착합니다. 줄이 낚싯대 끝과 연결되고 캐스팅 게이지가 사라집니다.
- [ ] 3~7초 정도 기다립니다(펫 버프가 있으면 더 짧음). 화면 중앙이 비어 있고 찌 주변 물결이 보입니다.
- [ ] 입질 시 찌의 `!` 및 안내를 확인합니다. F/버튼을 다시 **유지**하면 하단 포획 게이지가 찹니다.
- [ ] 50% 저항 구간에서 일단 놓고 **4초 안에 9번 누르기/놓기**를 합니다. 횟수·남은 시간·연타 게이지가 읽히고 성공 안내 후 일반 포획으로 돌아옵니다.
- [ ] 다시 유지하여 포획합니다. 작은 물고기/알 결과 카드 뒤 약 3.2초 후 평상시 화면으로 돌아옵니다. 가방에 1개만 추가됩니다.
- [ ] 다시 낚시해 저항에서 입력하지 않습니다. 시간 만료 후 실패 카드, 게이지·찌·줄 정리, 보상 없음, 다시 낚시 가능을 확인합니다.
- [ ] Charge/Waiting/Reel/Resist 각각에서 취소, B, Esc, 창 포커스 전환을 수행합니다. 입력이 계속 눌린 상태로 남거나 게이지가 고정되지 않아야 합니다.
- [ ] 낚시 중 부두를 벗어나거나 낚싯대를 해제합니다. 기존 서버 취소 규칙과 정상 UI 복귀를 확인합니다.

## 실제 건물과 두 핵심 루프

1. **판매:** 테스트 팩으로 물고기 3종을 준비하고, 청록 지붕 상점 카운터에 걸어가 E/터치로 엽니다. 피라미를 선택해 판매합니다. 20코인 증가·해당 개체 제거·중복 판매 불가를 확인합니다.
2. **사료:** 주황 지붕 공방으로 걸어가 엽니다. 농어로 고급 사료를 만듭니다. 농어 1개가 사라지고 고급 사료 1개가 늘어야 합니다. 피라미 고급 제작은 기존 규칙대로 거부됩니다.
3. **보관:** 스폰 뒤 정원에서 자신의 표식을 찾아 주황 콘솔을 엽니다. 물고기 탭에서 남은 개체를 배치합니다. 수족관에서 실제 모델이 헤엄치고 간판에 이름/레벨이 표시됩니다. 배치된 물고기에 판매/제작 버튼이 없어야 합니다. 회수 후에만 다른 장소에서 소비할 수 있습니다.
4. **업그레이드:** 내 수족관 탭의 레벨 카드를 선택해 업그레이드합니다. 100/250코인, 최대 Lv.3, 4/7/10 수용량을 확인합니다. 업그레이드 직후에도 상세 패널이 정상 유지되어야 합니다.
5. **알:** 내 수족관 옆에서 알 탭 → 사료 없음 → 배치합니다. 60초 타이머, 실제 알, 시간이 끝나면 알이 없어지고 펫 1마리, 부화 효과/안내를 확인합니다. 기본/고급 사료는 50/40초이며 1개만 소비됩니다.
6. **확률:** 알 배치 전 사료별 표시 확률을 비교합니다. Lv.1 기본 사료에서도 전설 확률은 0보다 커야 합니다. 레벨을 올린 뒤 새 알의 확률도 비교합니다. 이미 배치한 알은 배치 당시 설정을 유지합니다. 소수 표본의 부화 결과만으로 확률 구현을 판정하지 마세요.
7. **펫:** 펫 탭에서 장착·해제합니다. 한 마리만 따라다니고 실제 입질 시간이 줄며 포획 속도가 빨라집니다. 저항 4초/9회는 동일합니다. 일관된 비교를 위해 입질은 여러 번 평균, 포획은 동일 입력 시간으로 비교합니다.
8. **정상 보상:** 디버그 지급과 별도로 낚시를 반복해 물고기/알 획득 경로를 확인합니다. 5% 확률이라 짧은 세션에서 알이 나오지 않을 수도 있습니다. 임의 보상 주입을 정상 낚시 성공으로 기록하지 마세요.

## 저장·오프라인 부화·오류

- [ ] 임시 모드에서 Stop/Play 시 초기화되고, 도움말과 초기 안내가 이를 명시하는지 확인합니다.
- [ ] **새 비공개 테스트 Experience**에서만 `StudioPersistence=true` 및 Studio API 접근을 켭니다. 기존 운영 게임을 덮어쓰지 않습니다.
- [ ] 도움말 저장 상태와 Output 확인 → 물고기/알/사료/레벨/펫 장착 저장 → 정상 Stop/Play → 동일 데이터 복원.
- [ ] 사료 없는 알을 배치하고 저장 완료 후 Stop → 60초 이상 경과 → 같은 계정/Experience에서 Play → 펫 1개 → 다시 재접속해 동일 개체이고 재추첨/중복 지급 없음.
- [ ] 테스트 Experience에서 API 접근을 끈 영속 모드 실행: 명확한 오류·세션 거부/중지가 있어야 하며 임시 저장으로 조용히 바뀌면 안 됩니다. 검수 후 설정 복원.
- [ ] Studio와 Live DataStore 네임스페이스 분리, 180초 세션 잠금 및 40초 갱신을 기존 0.1 절차에 따라 검수합니다. 실제 Live 검증은 비공개 서버에서 별도로 수행합니다.

## 2인 테스트와 디버그 제한

1. Studio Test → Server & Clients / Local Server에서 **2 Players**를 시작합니다(Studio 버전에 따라 메뉴 명칭이 다를 수 있음).
2. 두 플레이어가 서로 다른 수족관을 배정받고 간판/본인 표식/가방 개체가 구분되는지 확인합니다.
3. A가 물고기·알을 배치하면 B 화면에서도 보이는지 확인합니다. B가 A의 콘솔을 눌러도 A의 조작 화면이 열리면 안 됩니다.
4. 서버 테스트 콘솔에서 확인한 A 개체 ID로 B 클라이언트의 `Remotes.Action`에 판매/회수/장착을 요청해도 B나 A 데이터가 변하지 않아야 합니다. 스팸 클릭으로 중복 소비·지급이 없어야 합니다.
5. A 퇴장/재입장 후 슬롯 해제·재할당, 저장 복구를 확인합니다. 두 클라이언트 낚시·찌·펫이 서로 섞이지 않는지 봅니다.
6. Studio에서 `StudioDebug=false`로 재실행해 메뉴가 숨겨지고 `travel`, `debugPack`, `debugHatch` 요청이 거부되는지 확인합니다. 실제 비공개 Live 서버에서는 설정이 true여도 IsStudio=false이므로 모두 거부되어야 합니다.

## 촬영할 증거와 기록

현재 확보된 Studio 스크린샷은 **없습니다**. 검수 후 다음 파일명을 권장합니다: `01-arrival.png`, `02-casting.png`, `03-resistance.png`, `04-bag-desktop.png`, `05-bag-portrait.png`, `06-aquarium.png`, `07-hatch-pet.png`. 화면 재현 그림은 실제 엔진 실행 캡처를 대신하지 않습니다.

기록 양식: 날짜 / 빌드 커밋 / Studio 버전 / 기기·해상도 / 언어 / 임시·영속 모드 / 항목 / 실제 결과 / PASS·FAIL·미실행 / Output 오류 / 캡처 경로.

실패 항목이 있으면 동작 상태와 재현 순서를 기록하고 수정 후 해당 경로를 재검수하세요. 실제 조작·CoreGui·소유권·저장 항목을 승인하기 전 공개 출시하지 않습니다.
